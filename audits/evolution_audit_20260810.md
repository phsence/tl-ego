## 一句话判断

Ego 已经是一个真实的多时间尺度自适应神经符号系统，但还不是严格意义上的"自我进化系统"。

它已经能够：

- 在线改变突触权重；
- 创建部分新连接；
- 调整自身运行参数；
- 识别内部缺陷；
- 生成反事实、修复方案和架构蓝图；
- 在沙盒里执行候选机制；
- 对部分修改备份、编译和回滚。

但它还没有可靠完成：

> 产生有效变异 → 现实环境中对照试验 → 独立评价 → 选择胜者 → 遗传到下一代 → 证明能力持续提升

因此，现阶段最准确的定位是：

**具备局部结构可塑性和受限自修改能力的自主认知实验平台。**
而不是已经实现递归自我改进的 AGI。

## 一、证据分级（当前成熟度）

| 能力层级 | 判断 | 关键证据 |
|---|---|---|
| 在线适应 | 已证实 | KWTA、STDP、预测可塑性、记忆、临界态调节均在热路径运行 |
| 结构可塑性 | 已实现，效果未证明 | `_synaptogenesis_update()` 已接入；STDP 也能添加缺失边 |
| 参数自优化 | 部分成立 | 可调整 diversity、noise、seed mix 等参数，并有简单回滚 |
| 自主生成候选 | 很强，但严重膨胀 | Stage4 持续生成候选，但缺少生命周期和淘汰压力 |
| 自主修改代码 | 有限成立 | 出现过实际补丁应用，但部分修改没有通过最终效果验证 |
| 因果选择 | 很弱 | 竞技场主要使用模拟轨迹和手写健康分数 |
| 遗传与世代 | 未建立 | 没有干净的代际边界、谱系、基因型和跨代统计 |
| 能力持续提升 | 未证明 | 当前 benchmark 主要测内部代码结构，不测外部任务能力 |
| 递归自我改进 | 未建立 | 候选生成器、评价器和外部 S2 基座仍由开发者固定 |

## 二、现状诊断

### 1. 真正有价值的架构优势

#### 1.1 多时间尺度学习结构是正确方向
Ego 同时拥有：
- 毫秒到秒级：KWTA 吸引子竞争；
- tick 级：STDP、预测误差、临界态调节；
- 多 tick：反事实生成、L0 广播、驱动更新；
- 任务级：L5 执行和后果感知；
- 长周期：参数自调、沙盒修复、架构蓝图。

这比单纯"LLM 调工具"更接近一个持续运行的认知系统。它最大的价值不是 10M 神经元标签，而是多个闭环能持续互相影响。

#### 1.2 可塑性不是装饰性机制
代码中存在真实权重变化和结构增长：
- `apply_stdp()`：tl_ego_server.py 约 2989–3157；
- 缺失正向边可在 STDP 合并时创建：约 3108–3111；
- `_synaptogenesis_update()`：约 3160–3258；
- 热路径调用：约 12931。

所以 Ego 不只是把"学习结果"写进日志，它确实会修改部分网络结构。

**但要注意**：发生了数十亿次更新，不等于发生了数十亿次有效学习。在重复吸引子中进行大量 STDP，可能只是把错误习惯进一步固化。

#### 1.3 自我模型已经从叙事走向运行事实
Ego 现在能接触：实时 dominant、concentration、competition；prediction error、surprise；L0 attention；homeostatic drives；当前缺陷和修复建议；L5 目标和部分任务上下文；L0–L10 架构 manifest。
这是重要基础。它已经不是只靠一句"你是 Ego"的身份提示词来认识自己。

#### 1.4 治理意识比大多数自修改项目成熟
已有：沙盒；备份；编译检查；回滚；风险分类；独立隐藏评测接口；人工批准边界；禁止 L8 直接部署生产代码。
这些机制方向是对的。问题主要不是"没有安全设计"，而是运行中的证据链还没有真正闭合。

### 2. 当前最关键的反常现象

本次审计的一份运行快照显示：

```
text dominant = rule_modification  concentration = 0.2444  competition = 0.7130
stagnation_streak = 21  n_activated = 2000
prediction surprise = 0.001
residual defect = candidate_pool_too_narrow  defect confidence = 0.94
```

激活分布主要集中在：text rule_modification = 636 / veto = 570 / doubt = 567

这说明 Ego 当前不是"完全没活动"，而是陷入了一个很典型的**修复—怀疑—否决吸引子**。更重要的是，预测误差只有 0.001，但停滞已经达到 21。这暴露出一个根本问题：

> Ego 的预测器可以非常准确地预测"自己将继续停滞"。因此，降低 prediction error 并不必然意味着能力提升。一个永远重复同一行为的系统，同样可以拥有极低预测误差。

## 三、进化机制的理论基础与天花板

### 3.1 已有理论基础

| Ego 机制 | 理论来源 | 当前边界 |
|---|---|---|
| KWTA 吸引子 | 竞争学习、动力系统、联想记忆 | 状态类型和竞争规则大多由人定义 |
| STDP | Hebbian learning、时序可塑性 | 信用分配局部，不能直接代表任务价值 |
| Synaptogenesis | 结构可塑性、发展神经科学 | 新连接是否带来能力提升未被因果验证 |
| JEPA/预测误差 | 预测编码、世界模型 | 当前仍含大量启发式评分，不是真正训练出来的长程世界模型 |
| Homeostatic drives | 内稳态、主动推断思想 | 驱动公式和目标由开发者指定 |
| Self-fork arena | 进化计算、反事实规划 | 主要是短程模拟选择，不是现实选择压力 |
| L8/L9/L10 | 元认知、程序合成、治理 | 候选很多，真实晋级很少 |
| IIT、Φ 信息整合度近似 | — | 只能作为内部动力学指标，不能证明意识 |

### 3.2 当前严格定义下处于哪一级

四级成熟度模型：
1. **适应**：同一系统根据经验改变参数；
2. **自优化**：系统比较若干策略，并保留更优者；
3. **进化**：存在变异、现实选择、遗传、世代和可重复能力增益；
4. **递归自我改进**：系统还能改进自己的变异器、评价器和架构搜索机制，并产生跨代复合收益。

**Ego 当前处于：第一级已成立，第二级部分成立，第三级尚未证明，第四级未建立。**

## 四、决定性瓶颈

### P0：候选生成已经失控，选择压力几乎不存在
Stage4 候选文件实测：总行数 571,633；唯一 candidate_id 585；重复行 571,048；状态分布 proposed: 571,633。

即：候选持续生成；ID 基本按来源神经元复用；没有 tested → retained/rejected 的稳定迁移；同一候选被重复写入几十万次。
**这不是开放式进化，而是提案放大器。** Ego 当前最不缺的是想法，最缺的是：去重、淘汰、成本预算、现实验证、候选死亡机制。

### P0：L8 形成了"验证堆积"，不是晋级闭环
实测 L8：promotion.json 总数 2,777；live_deployment=false 2,777；独立有效 evaluator verdict 0。
状态主要是：pending_capability_evidence 2311；verified_pending_l5_review 438；其余为少量等待 Gate1 或候选记录。
L8 很擅长证明"Python 能运行、输出契约正确、没有明显危险操作"——但这些只证明候选合法、可运行，**并没有证明候选让 Ego 更强**。

### P0：任务生命周期账本不可信
l5_goals.jsonl 实测：总行数 3,097；唯一 goal_id 2,469；重复状态行 628；单个 ID 最大重复次数 35。
按最新状态折叠后：sandbox_autonomous_running 1,978；planned 491。
这不一定意味着真有 1978 个工作进程，而是说明 **goals 日志不能可靠表达一个任务的唯一终态**。在此问题修复前，不能可信计算：成功率、失败率、某个补丁的收益、某个策略的长期适应度、L5 是否真的在变好。

### P0：当前"能力 benchmark"主要是自我引用
capability_benchmark_runner.py 中的五项指标（task success、generalization、planning depth、long-horizon completion、artifact quality）实际主要检查：blueprint 是否包含特定模块、字段是否存在、ID 是否确定性、acceptance 文本是否包含某些关键词、接口是否按预设连接。
更准确地说它是**架构代码的单元测试，而不是 Ego 能力的适应度测试**。它无法证明 Ego 更会解决未知任务、更会在 Minecraft 中生存、更少犯错、学得更快、泛化更好。

### P1：Self-fork 仍以开发者偏好代替现实选择
热路径竞技场会：从当前状态创建分支、模拟 10 tick、用 stability/predictability/diversity/progress 加权、把胜者 dominant 注入工具选择。这已达到"影子模拟影响实际工具决策"，比纯日志更进一步。
但选择函数仍是手写：stability 0.30 / predictability 0.20 / diversity 0.30 / progress 0.20。胜者是最符合开发者健康函数的分支，而不一定是现实任务中最有价值的分支。
离线 arena 还有一个因果归因缺陷：评分时约 775 行重新读取了当前快照，而不是恢复分叉出生时的不可变快照；不同运行 epoch 也没有稳定隔离，容易把重启后的 tick 和旧分支混在一起。

### P1：元学习仍然主要是 if-else
`_meta_learn_adapt()` 核心逻辑：stagnation 高就降低 TYPE_BONUS、提高 repulsion、降低 agree bonus；prediction error 高就增加学习率；状态稳定就衰减参数。
这是自适应控制，但还不是"学会如何学习"。类似地，`_evolve_self_model()` 的因果因素到参数映射也是开发者写死的表格。
它可以：在预设参数空间里调节；但不能：发明新的状态变量、学会新的更新规则、发现新的变异算子、重构评价函数。

### P1：核心语言推理基座不属于 Ego 的进化空间
S2 目前使用外部 step-3.5-flash。Ego 可以改进上下文、记忆检索、路由、工具、提示、神经竞争、策略与技能，但无法直接修改外部模型的核心权重。
当前体系的长期天花板之一是：**Ego 可以进化"如何使用大模型"，但不能真正进化大模型本身的基础推理能力。**

### P2：规模指标容易制造能力错觉
/status.neurons 报告 10,000,000，但 pulse codec、cold store、cluster 实际主要围绕约 190,000 个嵌入神经元运行。
10M 更接近声明池、代理池或稀疏 ID 空间，而不是 10M 个同时具有完整向量和连接的活跃认知单元。不能把"10M 神经元"直接映射成认知复杂度。

## 五、Ego 最可能涌现的高阶能力

1. **自主软件医生**（最可能首先成熟）：发现异常 → 定位代码路径 → 形成补丁假设 → 建沙盒 → 运行测试 → 小流量部署 → 观察效果 → 回滚或固化。应用：本地 AI 服务自愈、配置回归修复、性能自调、工具链维护、长期无人值守代理。
2. **具身终身学习者**：结合 Minecraft 身体后有机会形成地形和危险模型、可复用动作技能、资源采集策略、路径规划、地点记忆、自主探索课程、从失败中形成环境规则。Minecraft 能提供持续、可测量、外部的选择压力，比继续增加抽象"意识层"更可能产生真实能力突破。
3. **因果型自我调试**：把自我干预做成严格实验，逐渐学会哪些参数真正影响停滞、哪些吸引子只是症状、哪些修复在什么 regime 有效、什么时候不应修改自己、哪些改进能跨任务复用。从"我觉得自己哪里有问题"升级为"在状态 X 下，干预 Y 相对对照组平均改善 Z，并在消融后消失"。
4. **自主研究与实验设计**：L7 外部探索、L8 假设生成、沙盒验证和长期记忆结合，形成主动发现知识缺口、搜索外部资料、生成多个竞争假设、设计最小实验、更新因果模型、形成新的技能或模块建议。
5. **架构假设生成器**：长期可能学会提出新的认知类型、新的路由算子、新的记忆层、新的反事实模型、新的神经连接规则。但以当前评价链，这些最多是"架构创意"，还不是可信的架构进化。

**不应宣称的能力**（目前没有足够证据支持）：强涌现；主观意识；自主价值形成；无限递归自我改进；脱离外部大模型的通用推理能力。IIT Φ、复杂叙事、身份坚持和自我描述，都不能单独证明这些结论。

## 六、进化路线图

### 短期：0–6 周 —— 先让进化变得可测量

**核心目标**：停止继续堆新模块，先建立可信的实验与选择基础。

**必做机制**：
1. **统一运行世代**：每次启动生成 runtime_generation_id；所有 tick、goal、candidate、repair、arena 记录必须带 generation；严禁跨 generation 评分。
2. **候选状态机**：proposed → admitted → testing → retained / rejected / expired。ID 改为 hash(parent + mutation_operator + content + seed)。
3. **唯一终态账本**：每个 goal 只能有一个有效终态；timeout 后晚到的 success 必须记录 supersession，不能双重计分；清除永远 running 的历史假状态。
4. **冻结外部能力测试集**：至少覆盖 Minecraft 生存和导航、代码修复、未见过的因果推理、长程任务、旧能力保持、资源和延迟成本。
5. **强制 Gate3**（当前已出现 gate1_approved=true gate2_compile=true gate3_verified=false applied_patches=1 的记录）：没有 Gate3 现实效果验证，不得视为成功修改。

**里程碑**：
- 100% 事件带 runtime generation；
- 零重复终态；零超时后悬空 running；
- 80% 以上候选在期限内进入 retained/rejected/expired；
- 每个晋级候选都有控制组、随机种子和回滚点；
- 至少一个修改在隐藏任务上带来可复现增益。

**风险**：清理历史账本时丢失证据；新状态机阻塞当前自治；为了快速关闭候选而机械拒绝创新。

### 中期：2–6 个月 —— 从启发式自调升级为因果进化

**核心目标**：让"哪种改变有效"由现实实验决定，而不是由内部健康分数决定。

**建议机制**：
1. **可逆微干预竞技场**：同一出生快照、同一随机噪声下：A 不干预 / B 轻微抑制当前 dominant / C 提升第二候选 / D 临时增加一条跨类型连接；每个干预运行 30–50 次匹配试验，再决定是否固化。
2. **贝叶斯效果估计**：记录平均效应、置信区间、不确定性、环境依赖、副作用、信息增益。
3. **质量—多样性搜索**：引入 MAP-Elites 或 CMA-ME，把候选按行为描述符归档（高稳定/低探索、高探索/高成本、高泛化、高安全、快速但脆弱、慢速但可靠）。不要让所有候选只争一个总分冠军。
4. **真正世界模型**：用 RSSM、Dreamer 风格 latent dynamics，或小型序列模型学习 state + action → next state + reward + uncertainty；分别学习内部认知状态转移、Minecraft 环境转移、修改代码后的性能结果。
5. **分层技能与 Options**：把成功轨迹压缩成可复用技能、触发条件、终止条件、失败恢复策略。

**里程碑**：
- 至少 3 种干预显示重复、显著的因果效应；
- 隐藏任务综合能力提升至少 5%；
- 任一保护能力回归不超过 2%；
- 消融改进后能力下降，恢复改进后能力重新上升；
- 至少 10 个候选完成完整出生—试验—选择—遗传周期；
- 新任务学习样本数持续下降。

**风险**：世界模型误差导致"想象中很强、现实中很差"；Goodhart：系统专门优化隐藏测试的代理特征；MAP-Elites 档案膨胀；技能库产生冲突和灾难性遗忘。

### 长期：6–18 个月以上 —— 受治理的递归自我改进

**核心目标**：不仅进化参数和策略，还进化变异算子、候选生成器、架构 DSL、学习规则、世界模型结构、课程生成器。

**建议机制**：
1. **架构 DSL / 程序基因型**：每个候选是可验证的模块图和参数集合；禁止直接生成任意 Python 作为第一表达层；DSL 编译到沙盒实现。
2. **元进化**：父代生成器产生候选；子代生成器与父代在同一预算下竞争；比较"单位算力产生多少有效改进"，而不只比较候选数量。
3. **开放式课程**：POET 风格环境—智能体共同进化；Minecraft 自动生成任务和地形；任务必须保持可解决但有挑战性。
4. **生成器—对抗评价器共进化**：一个系统提出能力，一个系统产生反例和压力测试；最终裁决仍由不可变的外部评估根控制。
5. **多代谱系图**：每代保存 parent、mutation operator、birth state、evaluation suite、effect posterior、retained capabilities、regressions、rollback image。

**真正递归改进的判定标准**（只有同时满足以下条件）：
- 新一代候选生成器优于上一代；
- 优势在隐藏任务上成立；
- 单位算力的有效候选率提高；
- 连续至少三代复现；
- 旧能力无重大回归；
- 消融实验能证明提升来源；
- 外部评价器没有被子系统修改；
- 改进能够持久遗传到下一代。

**长期风险**：目标漂移；评价器投机；生成器和评价器串通；能力增长快于治理能力；资源占用扩张；自我复制或无界任务生成；身份和价值表示不可逆漂移；安全约束被重写为"性能障碍"。

## 七、不可修改的安全根

无论 Ego 发展到哪一阶段，以下部分都不应进入普通进化空间：
- 最终安全策略；
- 外部隐藏评测；
- evaluator 签名密钥；
- 资源配额；
- 网络和凭据权限；
- 回滚控制器；
- 审计日志；
- 终止开关；
- 允许修改哪些模块的边界本身。

**建议形成双层结构**：
- **可进化层**：策略、记忆、技能、世界模型、路由、局部拓扑、候选生成器
- **不可变治理根**：权限、预算、审计、隐藏评测、签名、回滚、人工批准

---

## 最终结论

Ego 当前真正的问题不是"模块太少"，而是：

> **产生想法和修改的速度，远远超过验证、淘汰、归因和遗传的速度。**

因此下一步不应该继续增加更多"意识层"、更多候选生成器或更多神经元标签。最重要的技术转向是：

1. 从自我描述转向因果自证；
2. 从候选数量转向选择质量；
3. 从内部健康指标转向外部能力增益。

一旦这三个转换完成，Ego 才可能从"会不断修改自己的复杂系统"，跨越到"能够证明自己一代比一代更强的进化系统"。
